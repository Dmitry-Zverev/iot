# Схема топиков MQTT

Продумать её стоит **до** того, как появится десяток датчиков.
Переименовывать топики потом больно: придётся перепрошивать платы
и править все флоу разом.

## Правило

```
home / <комната> / <что измеряем>
home / <комната> / <чем управляем> / set
```

Строчные латинские буквы, без пробелов и кириллицы. Кириллица в топиках
технически допустима, но ломает половину инструментов отладки.

## Что уже используется в этом репозитории

| Топик                      | Направление | Значение              | retain |
|----------------------------|-------------|-----------------------|--------|
| `home/kitchen/temperature` | датчик →    | `22.45` (°C)          | да     |
| `home/kitchen/humidity`    | датчик →    | `45.20` (%)           | да     |
| `home/kitchen/pressure`    | датчик →    | `1013.25` (гПа)       | да     |
| `home/kitchen/status`      | датчик →    | `online` / `offline`  | да     |
| `home/kitchen/rssi`        | датчик →    | `-62` (дБм)           | нет    |
| `home/kitchen/relay`       | датчик →    | `ON` / `OFF` (факт)   | да     |
| `home/kitchen/relay/set`   | → датчику   | `ON` / `OFF` (приказ) | нет    |
| `home/node-red/status`     | Node-RED →  | `online` / `offline`  | да     |

## Два правила, которые экономят часы отладки

**1. Разделяй «приказ» и «факт».**
`relay/set` — это то, что ты хочешь. `relay` — то, что реально произошло.
Если слать команды в тот же топик, где публикуется состояние, получишь
бесконечный цикл: интерфейс шлёт команду → реле отвечает → интерфейс
считает это новой командой.

**2. `retain` — для состояния, без `retain` — для событий.**
Retained-сообщение брокер хранит и отдаёт каждому новому подписчику сразу
при подключении. Открыл дашборд — температура уже на месте, а не через
30 секунд, когда датчик соизволит прислать следующее значение.

Для команд retain не нужен и опасен: retained-команда `ON` переживёт
перезагрузку и включит реле сама по себе в самый неожиданный момент.

## Wildcard-подписки

| Шаблон               | Что ловит                                        |
|----------------------|--------------------------------------------------|
| `home/kitchen/#`     | всё по кухне, на любую глубину                   |
| `home/+/temperature` | температуру из всех комнат (`+` = ровно один уровень) |
| `#`                  | вообще всё — удобно для отладки                  |

## Как удалить залипшее retained-сообщение

Публикация пустого payload с флагом retain стирает его:

```bash
npm run listen "home/#"          # посмотреть, что висит
node -e "require('dotenv').config();const m=require('mqtt');
const c=m.connect('mqtt://localhost:1883',{username:process.env.MQTT_USER,password:process.env.MQTT_PASSWORD});
c.on('connect',()=>c.publish('home/kitchen/temperature','',{retain:true},()=>c.end()))"
```
