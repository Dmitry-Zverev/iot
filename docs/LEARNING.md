## Хорошая новость

Ты уже знаешь больше, чем думаешь:

- **Node-RED** внутри — это Node.js. В function-нодах пишешь обычный JS.
- **MQTT** — это pub/sub. Если работал с WebSocket, Redis pub/sub или
  очередями, модель уже знакома: publish/subscribe, топики, wildcard'ы.
- **ESPHome** заменяет C++ на YAML. Для 90% бытовых задач кода не нужно совсем.

Незнакомого всего два куска: физика (напряжения, подтяжки, пины) и то,
что устройство может просто молча пропасть — и это нормальный режим работы,
а не исключительная ситуация.

## План на 4 недели

### Неделя 1. MQTT и Node-RED без железа

Железо ещё едет — это не повод ждать.

1. `bash scripts/setup.sh` → `docker compose up -d`
2. Открой http://localhost:1880, вкладка **Песочница** — нажми на inject-ноду,
   посмотри вывод в панели «Отладка» справа.
3. Запусти виртуальный датчик: `npm install && npm run sim`
4. Открой http://localhost:1880/dashboard — стрелки приборов поехали.
5. `npm run listen "home/#"` — посмотри на сырой поток MQTT-сообщений.

Разберись с: топиками, wildcard `+` и `#`, флагом retain, QoS 0/1/2,
Last Will (сообщение «я умер», которое брокер разошлёт за отключившееся устройство).

- Документация Node-RED: https://nodered.org/docs/ (начни с раздела «Getting Started» → «Developing Flows»)
- Что такое MQTT, коротко и по делу: https://www.hivemq.com/mqtt-essentials/
- Спецификация человеческим языком: https://mqtt.org/getting-started/
- Поиск на YouTube: `Node-RED для начинающих`, `MQTT простыми словами`,
  `Node-RED умный дом с нуля`

### Неделя 2. Первая плата

1. Прошей ESP32 через **ESPHome** — `esp32/esphome/kitchen-sensor.yaml` готов,
   нужно только создать `secrets.yaml`. Это YAML, а не C++.
2. Убедись, что данные долетают: `npm run listen "home/kitchen/#"`
3. Погаси виртуальный датчик — дашборд должен продолжить работать на живых данных.

Если хочется понять, что происходит под капотом — в `esp32/arduino/` лежит
тот же датчик, написанный вручную на C++. Полезно прочитать, даже если
прошивать будешь через ESPHome.

- ESPHome: https://esphome.io/ (раздел Getting Started → ESP32)
- Список поддерживаемых датчиков: https://esphome.io/components/sensor/
- Arduino-ядро для ESP32: https://docs.espressif.com/projects/arduino-esp32/en/latest/
- Пошаговые проекты на ESP32 (лучший англоязычный ресурс): https://randomnerdtutorials.com/projects-esp32/
- По-русски, база по железу и датчикам: https://alexgyver.ru/
- Поиск на YouTube: `ESPHome ESP32 настройка`, `ESP32 MQTT датчик температуры`,
  `ESP32 распиновка для начинающих`

### Неделя 3. Автоматизации и хранение

Теперь начинается то, ради чего всё затевалось.

1. Напиши флоу: «если температура > 26 °C дольше 10 минут — включить реле».
   Пригодятся ноды `switch`, `delay` (режим rate limit), `trigger`.
2. Добавь уведомления в Telegram — пакет `node-red-contrib-telegrambot`
   через меню «Управление палитрой».
3. Подключи хранение истории: InfluxDB + Grafana. Node-RED сам ничего
   не сохраняет — без базы графики живут только пока открыта вкладка.

- Кулинарная книга флоу (готовые рецепты): https://cookbook.nodered.org/
- Библиотека нод — тут есть почти всё: https://flows.nodered.org/
- InfluxDB: https://docs.influxdata.com/influxdb/v2/
- Grafana: https://grafana.com/docs/grafana/latest/
- Поиск на YouTube: `Node-RED InfluxDB Grafana`, `Node-RED Telegram уведомления`

### Неделя 4. Решить, нужен ли Home Assistant

Node-RED — это конструктор логики. Home Assistant — готовая платформа
с интерфейсом, приложением на телефон, голосовыми ассистентами и
поддержкой пары тысяч устройств из коробки.

Они не конкуренты: типичная связка — Home Assistant как платформа плюс
Node-RED как движок сложных сценариев.

Стоит переходить, если хочешь управлять домом с телефона вне дома, подключать
зарубежные устройства (Xiaomi, Tuya, Zigbee) или интегрировать Алису.
Если задача — «собирать данные с датчиков и что-то по ним делать»,
хватит того, что уже собрано здесь.

- Home Assistant: https://www.home-assistant.io/docs/
- Связка HA + Node-RED: https://github.com/zachowj/node-red-contrib-home-assistant-websocket
- Поиск на YouTube: `Home Assistant с нуля`, `Home Assistant Node-RED интеграция`

  (а она начнёт). Нормальное расширение для VS Code.

## Грабли, на которые наступают все

**`localhost` для ESP32 — это сама ESP32.** В прошивке нужен IP компьютера
в локальной сети (`192.168.x.x`), а не `localhost` и не `127.0.0.1`.

**ESP32 не видит 5 ГГц Wi-Fi.** Только 2,4 ГГц. Если роутер отдаёт обе сети
под одним именем — придётся разделить их или временно отключить 5 ГГц.

**Питание от USB-порта компьютера часто не тянет.** ESP32 в момент передачи
по Wi-Fi потребляет до 500 мА импульсами. Симптом — плата бесконечно
перезагружается. Лечится нормальным блоком питания на 1 А и более.

**Пины ESP32 работают на 3,3 В, а не 5 В.** Подача 5 В на вход убивает плату.
Модули реле часто требуют 5 В для питания (VCC), но управляющий вход (IN)
у нормальных модулей понимает 3,3 В.

**GPIO 6–11 заняты флеш-памятью.** Использовать нельзя. GPIO 34–39 работают
только на вход и не имеют внутренней подтяжки.

**DHT22 привирает и капризничает по таймингам.** BME280 по шине I²C заметно
стабильнее и вдобавок меряет давление. Если ещё не купил — бери BME280.

**Устройство отваливается — это норма.** Wi-Fi моргнул, питание просело,
прошивка зависла. Поэтому в конфигах и прописан Last Will: брокер сам
сообщит «offline». Всегда обрабатывай случай «данных нет», а не только
«данные пришли».
